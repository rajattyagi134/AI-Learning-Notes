# Project 05 - Website RAG Chatbot

# Project Goal

Build a Retrieval Augmented Generation (RAG) system capable of answering questions from a website.

Example:

```text
User Question
↓
Website Retrieval
↓
LLM
↓
Answer + Citation
```

Unlike PDF RAG, the knowledge source is a website instead of a PDF document.

---

# What Is Website RAG?

Website RAG is a system that:

1. Extracts website content
2. Converts content into chunks
3. Creates embeddings
4. Stores embeddings
5. Retrieves relevant content
6. Sends context to LLM
7. Generates grounded answers

---

# Threshold Filtering

Definition:

Remove weak retrieval results.

Example:

```python

```

---

Example:

```text

```

```text

```

survive.

---

# Relative Thresholding

Definition:

Threshold based on best result.

Formula:

```text
Threshold =
Top Score × Ratio
```

---

# Why Relative Thresholding?

More adaptive than fixed thresholds.

# Important Interview Questions

## Q1. Why Did BeautifulSoup Fail On The React Website?

Answer:

BeautifulSoup only parses raw HTML and cannot execute JavaScript. React content is rendered dynamically in the browser.

---

## Q2. Why Did Playwright Work?

Answer:

Playwright launches a real browser, executes JavaScript, renders React components, and extracts the final content.

---

## Q3. What Is Client-Side Rendering?

Answer:

Content is generated inside the browser using JavaScript instead of being present in the initial HTML.

---

## Q4. Why Not Create One Embedding For The Entire Website?

Answer:

One embedding mixes multiple topics together, reducing retrieval accuracy and increasing context dilution.

---

## Q5. Why Use Section-Based Chunking?

Answer:

Sections represent natural semantic boundaries and align with user intent.

---

## Q6. What Is Semantic Chunking?

Answer:

Chunking content based on meaning and topic rather than arbitrary character limits.

---

## Q7. Why Is Metadata Important?

Answer:

Metadata enables citations, explainability, filtering, auditing, and source traceability.

---

## Q8. What Is Top-K Retrieval?

Answer:

Returning multiple relevant chunks instead of only the best match.

---

## Q9. Why Use Threshold Filtering?

Answer:

To remove weakly related chunks and reduce irrelevant context.

---

## Q10. What Is Grounding?

Answer:

Restricting the LLM to answer only using retrieved context.

---

## Q11. What Is Source Traceability?

Answer:

The ability to identify the exact source section and URL from which an answer was generated.

---

## Q12. Why Does Chunk Quality Matter?

Answer:

Poor chunks create poor embeddings, resulting in poor retrieval and poor answers.

---

# Key Lessons Learned

1. Website RAG starts with content extraction.
2. Modern websites often require browser rendering.
3. Playwright solves JavaScript rendering problems.
4. Semantic chunking is better than arbitrary chunking.
5. Chunk quality is more important than changing the LLM.
6. Metadata enables explainability.
7. Retrieval quality depends heavily on chunk design.
8. Top-K retrieval improves answer completeness.
9. Thresholding reduces irrelevant context.
10. Grounding reduces hallucinations.
11. Website RAG follows the same retrieval architecture as PDF RAG.
12. Most RAG systems differ mainly in data ingestion rather than retrieval logic.
